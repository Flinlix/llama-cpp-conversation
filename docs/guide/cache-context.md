# Your own cache context

`ChatWrapper(context=...)` takes any object that answers the protocol
`CacheContext`: the model's tokenizer, its tags, its chat template and the
sampling it recommends, and the cache a conversation is decoded into, with the
type one of its members takes: `DrawnSampling`, every sampling value set, from
`llama_cpp_conversation`. Nothing to subclass or register; the members are
checked where the context is adopted, so a missing one, or a method that does
not take the arguments its protocol method takes, positionally and by name, is
a `TypeError` from the constructor. A cache that can neither shift
(`can_shift`), cut its end (`can_cut_tail`) nor save a state (`save_state`
giving something other than `None`) is refused there with a `ValueError`: it
could go back to an earlier point only by decoding the whole conversation
again. The wrapper reads the [add-on file](add-on-files.md) itself, by
`model_path` where one is set and by the template `chat_template_text` gives,
and merges the sampling, so a context of your own gets both as one the wrapper
loads does; `recommended_sampling` gives what the model states for itself, by
`Sampling`'s field names other than `seed`, and each `sampled_tokens` call is
handed every value it draws with. A context gives its chat template as text
(`chat_template_text`) and the text of its end-of-sequence token
(`eos_token_text`), which a template may write as `eos_token`; the library
renders the template itself, in the sandboxed template environment chat
templates are written for, so a context renders nothing. Where the model's tags
lie in a text comes from its tokenizer alone: `special_tokens` lists the tags,
`is_special` tells one among the tokens of a text, `tokenize` with
special-token parsing on gives each tag in a text as its one token, and
`token_text` spells that token as the text holds it. A reply is generated by
the library's own loop through four steps: `sampled_tokens` draws,
`decode_generated` decodes what the generation adds, and `ends_generation` and
`token_bytes` read a drawn token, so a call is told apart and a reply ends the
same on every context; a call's closing tag is decoded with `prefill` asking
for no logits, since a result follows it, not a draw. `decode_blocks` says
whether `decode_generated` returns only once the decode is done; where it does,
each token's text is yielded before the token is decoded, as is the first
token of every generation. Two members are optional. `prepare_draws` is told,
once at load, before each generation's request is decoded and again before
it draws, the sampling it draws with and how many tokens a draw may withhold
at most, and answers whether the newest decode's logits still serve those
draws; where it answers `False` once the prompt is decoded, the library
decodes the prompt's last token again. A context without it is taken
to keep them. `longest_token_bytes` gives the most bytes one token of the
vocabulary stands for: a tool result longer than the room could ever spell is
then cut to that before it is tokenized. Without it such a result is tokenized
whole first. `save_whole_state`
and `restore_whole_state` keep and put back everything the cache holds, for
`kept_conversation_bytes`; a context that cannot may raise `RuntimeError` from
the first, and no conversation is then kept. `chat_template_text` takes a
`template_name`: `None` for the default template, else the name of a further
one the model ships, such as `TOOL_USE_TEMPLATE` from `llama_cpp_conversation`;
a name the model ships no template of answers `None`. A context whose
`chat_template_text()` answers `None` is refused where it is adopted, as a
model that ships no chat template is. `model_fingerprint` names the model its
tokens are valid for: `generated_turns` restore turns as generated only on a
context whose fingerprint is the one they were saved on. Its token ids must lie
from -65,536 to 1,048,575: an eviction searches the cache's tokens for the
stretch it dropped, and an id outside that range fails that search.
`llama_cpp_conversation.testing` ships a worked one, `FakeContext` in
`llama_cpp_conversation/testing/fake_context.py`, over a list of ints and a
scripted model, with the small invented templates it renders in
`llama_cpp_conversation/testing/invented_templates.py`, for tests of code that
drives a wrapper without loading a model.

**How `FakeContext` behaves.**

- It renders with a template's own renderer, the one a model is loaded with.
  Only the tokenizer is a stand-in: one token per character, and, where
  special-token parsing is on, one per tag-shaped text. A tag typed into a
  message is tokenized with parsing off, so it stays its characters. With
  `merges`, a space also merges with the letter or digit after it.
- The tags it lists are those the template spells or writes, and each closing
  tag among them without its slash. Where the fixture says `adds_bos`, `BOS`
  comes first where the opener is asked for.
- A generation draws, in this order: the next of `call_script` where a call's
  opening may be drawn, else the next of `replies` without the tokens
  withheld, else `gen_text` cut or padded to `gen_tokens`; then the first tag
  of the closing after a reply (the fixture's `turn_end_token`, else its
  end-of-sequence tag) unless that tag may not be drawn; then the end of
  generation. The end-of-sequence tag, and each tag the fixture's
  `ends_generation` lists, end a generation too.
- `before_reply` is handed the cache's text before each generation, so that a
  test can compare it with the template's render at that moment.
- Every decode lands at the cache's end, and each cache edit asserts the
  ability it needs, so a wrapper that cuts a cache that cannot cut, or shifts
  one that cannot shift, fails there.
- `stated_render` renders with the variables the fixture states for
  `reasoning` and an effort level, none read off the template. A
  conversation begun with tools is written with the fixture's template for
  tools, where it gives one.
